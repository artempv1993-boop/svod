# Свод по опросу владельцев процессов — как устроен сайт

Публичный одностраничный свод: **https://artempv1993-boop.github.io/svod/**
Репозиторий: `github.com/artempv1993-boop/svod` (GitHub Pages из ветки `main`, папка `/`).

Сайт статический — это один самодостаточный `index.html` (данные вшиты внутрь как JSON,
всё рисуется JavaScript на стороне браузера). GitHub Pages отдаёт только статику, поэтому
сервер там не крутится; актуальность обеспечивается **пересборкой и push** (см. «Как обновить»).

```

        │
        ▼  пишет
svod-opros\data-1a.json      ← «сырой» свод: отделы (чат), направления, бот
        │
        ├── build\roster.mjs  → roster.json + dept2upr.json  (штатка + карта отдел→управление из Битрикса)
        ▼

        │  пишет
```

Коллектор `svod-1a.mjs` — **не мой** файл, это движок соседнего проекта; он же поднимает
локальный просмотр на `localhost:8137` и обновляется по расписанию. Сайт на GitHub берёт
из него только `data-1a.json`.

## Правила распределения (реализованы в `build\gen_payload.py`)

1. **Отдел — по ФИО автора** (`owner` документа), сверка со штаткой Битрикса.
   Управление — родительское подразделение отдела; карта `dept2upr.json` строится
   **динамически из оргструктуры**, поэтому новые отделы подхватываются сами.
2. **Чат и бот не смешиваются как источники**, но распределяются по одному правилу — по ФИО.
   Товаровед, сдавший и в чате, и в боте, — **одна запись** с суммой (метка «чат+бот»).
3. **Бот, ФИО не опознано, но должность товаровед/скупщик** → в отдел «Товароведы»
   Коммерческого управления, строкой «**+N из бота — ФИО не определено**» (метка «+ БОТ»).
4. **Бот, опознан как не-товаровед** (аналитик, руководитель) → в его отдел по ФИО.
5. **Подсчёт по анкетам**: каждый уложенный документ/анкета считается один раз.
   Контроль в конце: сумма по управлениям + «не определён» = всего в базе.

> Что пока НЕ автоматизировано: сведение имени-без-фамилии из бота («Олеся», «Регина»)
> к конкретной точке/ОП — это ручная сверка ФИО, ведём отдельно.

## Очистка и дедупликация ФИО (`build\roster.mjs`)

Штатка Битрикса **грязная**: в поле имени встречаются эмодзи (`✅`, `❗`), номер ОП, дата приёма
(`с 1.06.2022`), название точки (`Новостройка`), должность — иногда **без пробела** (`Эльвина✅`).
Плюс один человек попадает в выгрузку **несколько раз** — с разным порядком Фамилия/Имя и в разных
отделах. Без очистки владелец документа не сопоставляется, отдел определяется неверно, отчётность врёт.

`roster.mjs` это чинит и отдаёт **единый чистый источник** `roster.json`, который используют
и сайт (`gen_payload.py`), и движок свода (`svod-1a.mjs` читает тот же файл):

1. **Очистка ФИО.** Сначала снимаются номера ОП/КМ и даты, затем **всё не-кириллическое**
   (это отклеивает прилипшие эмодзи/цифры/латиницу), затем токен-фильтром убираются роли
   (`товаровед`, `кассир`, `оценщик`…) и названия точек. `\b` с кириллицей в JS **не работает** —
   поэтому фильтр по токенам, а не regex со словесной границей.
2. **Дедупликация.** Один человек с разным написанием сводится в одну запись по ключу
   **«фамилия + имя»** (первые два токена, отсортированы — порядок Фам/Имя нормализуется).
   Только фамилия+имя, а **не любая пара токенов**: иначе тёзки по имени+отчеству с разными
   фамилиями (Чернова Ирина Борисовна / Сиухина Ирина Борисовна) слились бы ошибочно.
3. **aliases.** Все написания ФИО человека сохраняются в `aliases` — по ним идёт сопоставление
   владельца документа, в каком бы порядке ни было записано имя в `owner`.
4. Лучший вариант ФИО для отображения — с настоящим **отчеством** (`-вна`/`-вич`) в 3-м токене,
   а не с названием точки.

Диагностика после `node roster.mjs`: строка «N человек (свёрнуто дублей K)». Если K резко вырос
или в консоли видны слияния разных фамилий — проверить логику ключа.

## Три вкладки сайта

Сайт трёхвкладочный (`.tab` / `data-tab`, панели `#panel-svod` / `#panel-survey` / `#panel-overview`):

1. **«Первая итерация опроса»** — свод по укладке Слоя 1А (680+ док., чат + Telegram-бот `@ARM_opros_bot`), данные `payload.json` / `DATA`.
2. **«Вторая итерация»** — новый бот **`survey-bot`** (v2, `Documents\survey-bot`), три сценария: **Основной опрос** (process_survey), **Доопрос** (gap_survey), **Фото рабочего дня** (workday_photo). Данные `payload2.json` / `DATA2`.
3. **«Общий свод»** — общая картина: направления первой итерации + итоги обеих итераций рядом (меряют разное — документы vs сессии, не суммируются).

**Данные второй итерации — по фактически выложенным файлам бота** (не по журналу сессий):
- `survey-bot\scripts\gen_site_payload.py` читает **каждый файл** в `storage\output\<сценарий>\…`,
  парсит frontmatter, резолвит автора/отдел/управление по `bitrix_id` из справочника, и
  **классифицирует качество**: `содержательный` (process — `confidence≥0.4` и процесс определён;
  gap — `questions_closed(+soft)≥1`; workday — `полнота≥0.4`) / `частичный` / `пустой` (без владельца).
  Запуск: из `Documents\survey-bot` → `PYTHONPATH=src .venv\Scripts\python.exe scripts\gen_site_payload.py`.
- `build_site.py` подставляет `payload2.json` в `/*__PAYLOAD2__*/null` (если файл есть).
- **ПДн:** телефоны не выгружаются; поимённо показаны авторы непустых файлов, пустые/частичные — счётчиком.
  `payload2.json` — в `.gitignore` (как `payload.json`).

Чтобы обновить обе вкладки:
```bash
# 1) свод по укладке (как обычно)
node "C:\Users\proninav\Documents\svod-opros\src\svod-1a.mjs" --once
node roster.mjs && python gen_payload.py
# 2) охват survey-bot
cd "C:\Users\proninav\Documents\survey-bot" && PYTHONPATH=src .venv\Scripts\python.exe scripts\gen_site_payload.py
# 3) сборка + публикация
cd "C:\Users\proninav\Documents\svod-site\build" && python build_site.py && python gen_report.py
cd "C:\Users\proninav\Documents\svod-site" && git add index.html && git commit -m "свод: обновление" && git push
```

## Как обновить сайт (после укладки новых файлов)

Из папки `C:\Users\proninav\Documents\svod-site\build`:

```bash
node "C:\Users\proninav\Documents\svod-opros\src\svod-1a.mjs" --once
node roster.mjs
python gen_payload.py
python build_site.py
python gen_report.py
```

Затем из `C:\Users\proninav\Documents\svod-site`:

```bash
git add index.html && git commit -m "свод: обновление" && git push
```

- `gen_payload.py` в конце печатает **КОНТРОЛЬ … OK** — суммы должны сойтись.
- `report.md` (справка) копируется в хранилище вручную (см. ниже), в паблик-репо не идёт.
- Дата снимка на сайте берётся автоматически из времени файла `data-1a.json`.

## Приватность

Ссылка **публичная** (как портал коллеги на `tikhaziev-coder.github.io`). В паблик-репозиторий
попадает **только `index.html`**. Файлы с ПДн (`roster.json` — 497 ФИО и № ОП, `payload.json`,
`report.md`, `dept2upr.json`) и вебхук (`.bitrix.env`) — в `.gitignore`, наружу не уходят.
На странице стоит `noindex` (из поиска скрыта).
